# User Administration

## Scope

User Administration is available only to authenticated users with `users.manage`. Role and permission administration is available only to users with `roles.manage`.

## Create Employee

1. Sign in as a `system_admin`.
2. Open the portal dashboard.
3. Use **User Management** to choose account type, department, start date, email, username, display name, temporary password, and roles.
4. The backend hashes the temporary password, stores `must_change_password=true`, creates the first department history row, and writes `user_create` plus `employee_created`.

The UI clears the temporary password field after submit and never stores passwords in browser storage.
Employee code is generated by the backend for employee accounts. It must follow `HCS_<DEPARTMENT><SEQUENCE>`, for example `HCS_HR001`, and cannot be changed after it is assigned.
Technical accounts have no employee code and do not increment department sequences.
Start Date and End Date use date-only values. The API accepts and returns `YYYY-MM-DD`; the UI displays `DD/MM/YYYY` and does not expose hour, minute, or second inputs.

## Assign Roles

Use **Roles** in the user table. The backend validates every role code before writing `user_roles` and records `user_roles_change`.

Protection rules:

- The last active `system_admin` cannot lose the `system_admin` role.
- A user cannot remove the final active admin path by role changes.

## Lock, Unlock, And Status

Supported status values are `active`, `disabled`, `locked`, and `pending`.

When an account is disabled or locked, active sessions are revoked and `user_status_change` is recorded.
When employment status becomes `terminated` or `retired`, the employee code is retained, active sessions are revoked, and the current department history row is closed.

Protection rules:

- An admin cannot disable or lock their own account.
- The last active `system_admin` cannot be disabled or locked.

## Reset Password

Use **Reset** on a user row and enter a new temporary password of at least 12 characters.

The backend:

- hashes the password;
- sets `must_change_password=true`;
- revokes active sessions;
- writes `password_reset_by_admin`;
- never returns the password in JSON.

The next login forces the user to change password before dashboard access.

## Revoke Sessions

Use **Revoke** on a user row. The backend revokes active sessions for that user and writes `sessions_revoked`.

## Role And Permission Administration

Use **Role Management** for role creation and permission assignment.

Role code rules:

- lowercase ASCII;
- starts with a letter;
- may contain numbers, dots, and underscores.

Protection rules:

- `system_admin` cannot lose `users.manage`.
- `system_admin` cannot lose `roles.manage`.
- `system_admin` code is protected.

## Department Administration

Users with `departments.manage` can create departments, update department name/description/status, and transfer employees between departments.

Department code rules:

- uppercase ASCII;
- 2 to 10 characters;
- may contain `A-Z`, `0-9`, and `_`.

Departments with active employees cannot be deactivated until employees are transferred.

## Department Transfer

Use **Transfer** on a user row. The backend:

- validates the target department is active;
- rejects transfer to the current department;
- preserves `employeeCode`;
- closes the active history row with `effective_to`;
- creates a new active history row;
- updates the user's current department;
- writes `employee_department_transfer`.

## Audit Actions

The following actions are recorded:

- `user_create`
- `user_update`
- `user_status_change`
- `user_roles_change`
- `password_reset_by_admin`
- `password_changed`
- `sessions_revoked`
- `role_create`
- `role_update`
- `role_permissions_change`

Audit metadata must not contain plaintext passwords, OTPs, tokens, cookies, or recovery tokens.

## PowerShell Checks

```powershell
$base='http://127.0.0.1:4173'
$csrf=Invoke-WebRequest "$base/api/auth/csrf" -SessionVariable session
$csrfToken=($csrf.Content | ConvertFrom-Json).csrfToken
$loginBody=@{ email='admin@example.test'; password='change-this-local-password' } | ConvertTo-Json
Invoke-WebRequest "$base/api/auth/login" -Method POST -ContentType 'application/json' -Headers @{ 'x-csrf-token'=$csrfToken } -Body $loginBody -WebSession $session
Invoke-RestMethod "$base/api/admin/users" -WebSession $session
$createBody=@{
  email='employee@example.test'
  username='employee'
  displayName='Employee'
  password='temporary-password-123'
  roles=@('employee')
} | ConvertTo-Json
Invoke-RestMethod "$base/api/admin/users" -Method POST -ContentType 'application/json' -Headers @{ 'x-csrf-token'=$csrfToken } -Body $createBody -WebSession $session
```
